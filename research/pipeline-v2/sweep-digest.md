# Pipeline Architecture Patterns in Top Open-Source Quant Frameworks
## A survey for the cycle-stack desk (2 people, free data, India, 2026-2040)

**Scope note.** This report covers architecture only — module boundaries, dataflow, interfaces, feedback loops, validation tooling, online/offline separation, monitoring — not alpha content. Everything cross-checked against live docs/repos as of 2026-09-01 is cited; anything from prior knowledge that I could not re-confirm is tagged **[VERIFY]**. ## 1. Microsoft Qlib (~48k stars per repo page, Sept 2026) — the closest thing to a reference architecture for this desk

**Repo:** [microsoft/qlib](https://github.com/microsoft/qlib) | Docs: [Workflow](https://qlib.readthedocs.io/en/stable/component/workflow.html), [Recorder](https://qlib.readthedocs.io/en/v0.9.7/component/recorder.html), [Online Serving](https://qlib.readthedocs.io/en/latest/component/online.html), [Task Management](https://qlib.readthedocs.io/en/latest/advanced/task_management.html)

**End-to-end dataflow.** Four layers: (1) **Infrastructure** — a data server with an expression engine, expression/dataset caching, and a **point-in-time database** (built for exactly the vintage problem: quarterly fundamentals keyed by announcement date, not period date); (2) **Learning framework** — supervised/RL/market-dynamics paradigms; (3) **Workflow** — Information Extractor -> Forecast Model -> Portfolio Generator -> Order Executor -> Analyser; (4) **Interface** — `qrun`, which runs an entire experiment (data, features, train, inference, backtest, analysis) from a single YAML config.

**Key design elements:**
- **Config-as-experiment (`qrun`).** One YAML file *is* the experiment. Every run — data hash, features, model params, backtest window — is a reproducible artifact. This is pre-registration made executable.
- **Recorder pattern.** `QlibRecorder` (the global `R`) wraps an `ExpManager` (concrete: `MLflowExpManager`) in a hierarchy Experiment -> Recorders, auto-logging params, metrics, signals, and artifacts of every train/inference/eval phase; browsable via `mlflow ui`.
- **Task Management.** `TaskGen`/`RollingGen` generate task lists from a template across rolling date segments; `TrainerR`/`TrainerRM` (MongoDB-backed task pool) run them; `Collector`/`Group`/`Ensemble` (incl. `AverageEnsemble`, `RollingEnsemble`) merge results. Rolling retrain is thus a *first-class generative object*, not a for-loop in a notebook.
- **Online Serving.** `OnlineManager` + `OnlineStrategy` (concrete: `RollingStrategy`) + `OnlineTool` manage **which model is "online" at which time, with a recorded history**; `first_train()`, `routine()` (simulate every scheduled rotation between two dates — i.e., the *deployment loop itself is backtestable*), `delay_prepare()`. This is the cleanest open-source statement of online/offline separation in quant.
- **Nested decision execution** — daily portfolio decisions and intraday execution simulated jointly as an outer/inner loop.
- **Concept drift** — rolling retraining plus DDG-DA (meta-model that anticipates distribution shift) as pluggable "market dynamics" handlers.
- **RD-Agent integration** (see §12) for automated factor/model R&D.

**Gets right (vs our v1):** the Recorder + qrun combo automates what our pre-registration/trial-ledger does manually; the OnlineManager's "who was online when" ledger is exactly the missing formal object between our decay ledger and half-life re-estimation; PIT database as an infrastructure-layer concern, not a per-script discipline; rolling-retrain-as-task-generator with ensembling across windows (a soft, hysteresis-friendly alternative to hard model switches).

**Gets wrong / avoid:** the model zoo culture (25+ deep nets benchmarked on the same A-share dataset) is an overfitting factory — the *architecture* is separable from that culture and only the architecture should be imported; MongoDB + task-pool infra is overkill for 2 people (use `TrainerR`-style simplicity: SQLite/files); A-share-centric data assumptions mean we'd use the *patterns*, not the code; maintenance has visibly shifted toward RD-Agent, so treat Qlib as a design document more than a dependency.

## 2. QuantConnect LEAN — typed contracts between pipeline stages

**Repo:** [QuantConnect/Lean](https://github.com/QuantConnect/Lean) | Docs: [Algorithm Framework](https://www.quantconnect.com/docs/v2/writing-algorithms/algorithm-framework/overview), [Algorithm Engine](https://www.quantconnect.com/docs/v2/writing-algorithms/key-concepts/algorithm-engine)

**End-to-end dataflow.** Two distinct layers. (a) **Engine:** modular handlers wired by config — DataFeed (FileSystemDataFeed vs LiveDataFeed behind one interface), `AlgorithmManager` (the heartbeat loop that synchronizes all subscriptions into one time-ordered `Slice`), TransactionHandler, ResultHandler — each swappable without touching the others. (b) **Algorithm Framework:** a fixed five-stage pipeline with *typed data contracts*:

Universe Selection -> **Alpha model** (emits `Insight` objects: direction, magnitude, confidence, **period/expiry**) -> **Portfolio Construction** (Insights -> `PortfolioTarget` objects: target holdings) -> **Risk Management** (a separate pass that *transforms the PortfolioTarget collection*, e.g. trims, vetoes) -> **Execution model** (works targets into orders).

Also notable: "reality models" (fees/slippage/fill/margin as pluggable per-market models) **[VERIFY exact naming — docs blocked by proxy]**, scheduled events, identical algorithm code for backtest and live via handler swap.

**Gets right (vs v1):** our v1 describes stages in prose; LEAN shows the payoff of *typed interfaces* — an Insight that carries its own **expiry/half-life and confidence** is precisely the object our decay-haircut logic wants to operate on, and a risk stage defined as "a pure function over the target collection" is exactly what our drawdown governor and reduce-only overlay should be formalized as. Live/backtest symmetry via interface swap (not code duplication) is the standard our Stage-1 emitter should meet.

**Gets wrong / avoid:** heavyweight C# monolith with a commercial data-cloud gravity well; the framework's default statistical culture (no purged CV, no deflated Sharpe) is weaker than ours; universe selection coupled to their data store. Borrow the contracts, never the engine.

## 3. vectorbt (~6.9k stars) — the screening tier

**Repo:** [polakowo/vectorbt](https://github.com/polakowo/vectorbt) | [Docs](https://vectorbt.dev/)

**Dataflow.** Everything is a NumPy array; thousands of parameter configurations are broadcast into one multidimensional array and simulated at once (Numba, optional Rust kernels; ~1M order fills in 70-100ms). Two modes: pure vectorized (signals/orders as arrays) and callback-based event-driven for path-dependent logic.

**Gets right:** hypothesis screening at four orders of magnitude lower cost than event-driven replay — the correct *first tier* of a research funnel. Its own docs concede sequential mechanics (trailing stops, stateful sizing, portfolio-level constraints) break the vectorized abstraction — an honest boundary statement.

**Gets wrong / avoid:** the product's whole pitch ("run thousands of ideas before others finish one") is a p-hacking engine unless every sweep cell is counted as a trial; open-source version semi-frozen while development moved to paid vectorbt PRO. **Rule if adopted: a vectorbt-style sweep is admissible only if the sweep's full grid size is auto-written to the trial ledger and feeds the deflated-Sharpe trial count.**

## 4. zipline-reloaded (~1-2k stars [VERIFY]) — the Pipeline API is the important artifact

**Repo:** [stefan-jansen/zipline-reloaded](https://github.com/stefan-jansen/zipline-reloaded) | [ML4T walkthrough](https://stefan-jansen.github.io/machine-learning-for-trading/08_ml4t_workflow/04_ml4t_workflow_with_zipline/)

**Dataflow.** Data **bundles** (columnar bcolz OHLCV + SQLite metadata, with **on-the-fly split/dividend adjustment at read time** — the adjusted view is always as-of the simulation date, never today's); **trading calendars** as a separate abstraction; the **Pipeline API** — a declarative DAG of Factors/Filters/Classifiers computed cross-sectionally each day over a *dynamic point-in-time universe*, feeding the event loop. Companion `alphalens-reloaded` gives standardized factor tear sheets (IC decay, quantile returns, turnover) *before* any backtest.

**Gets right:** the cleanest separation anywhere between **cross-sectional feature computation (Pipeline)** and **event-driven simulation** — our Return Engine's sleeve scoring is a Pipeline in all but name and would benefit from being one: declarative factor graph, computed only over the point-in-time investable universe (survivorship-safe NIFTY-750 membership), with adjustments applied as-of. The alphalens pattern — *cheap standardized factor evaluation as a stage-gate before backtesting* — is a research-process improvement.

**Gets wrong / avoid:** bcolz is aging tech; bundles are OHLCV-only (fundamentals need bolt-ons); community-maintained single-maintainer risk. Again: borrow the pattern (factor DAG over PIT universe membership tables), not the storage engine.

## 5. Riskfolio-Lib (~3.8k stars) — a solver, not an architecture

**Repo:** [dcajasn/Riskfolio-Lib](https://github.com/dcajasn/Riskfolio-Lib) | [Docs](https://riskfolio-lib.readthedocs.io/)

cvxpy-based optimizer with 26 convex risk measures, HRP/HERC/NCO clustering allocators, and rich constraint grammar. **Gets right:** breadth of risk measures and hierarchical allocators for the equity cross-section. **Gets wrong:** it has *no pipeline* — no data layer, no validation, no walk-forward, no experiment tracking; docs themselves note open-source solvers (CLARABEL/SCS) fail or crawl on some models and recommend MOSEK (commercial). For this desk: skfolio supersedes it architecturally; at most keep Riskfolio as a second-opinion solver for HRP-style allocations inside Stage 3's risk-budgeting-only role.

## 6. skfolio (~2.3k stars, arXiv paper July 2025) — validation-first portfolio construction

**Repo:** [skfolio/skfolio](https://github.com/skfolio/skfolio) | [Paper](https://arxiv.org/pdf/2507.04176)

**Dataflow.** Everything is a scikit-learn estimator: **prior estimators** (Empirical, BlackLitterman, factor models, EntropyPooling, OpinionPooling, SyntheticData/VineCopula for stress paths) -> **moment estimators** (ShrunkMu, DenoiseCovariance, DetoneCovariance, GerberCovariance, LedoitWolf...) -> **optimization estimators** (MeanRisk, RiskBudgeting, HRP/HERC, NestedClustersOptimization, **StackingOptimization**) -> `Portfolio`/`MultiPeriodPortfolio` result objects. Composition via `Pipeline` (pre-selection transformers like `SelectKExtremes`, `DropHighlyCorrelatedAssets`); validation via **`WalkForward`** and **`CombinatorialPurgedCV`** as library primitives; hyperparameters via `GridSearchCV` (trial counts enumerable by construction); **uncertainty-set estimators** (bootstrap sets on mu/covariance) for robust optimization.

**Gets right (vs v1):** our estimation standards (purged/embargoed CV, walk-forward, Ledoit-Wolf) exist here as *tested library primitives instead of desk-written code* — less bespoke code for 2 people to maintain and audit; `GridSearchCV`-style declared grids match our "grids and ranks only, no magic numbers" rule and make trial counts mechanically countable for deflated Sharpe; StackingOptimization is a clean pattern for combining our five factor sleeves at the construction layer; VineCopula synthetic paths give a free-data stress-testing rig for the drawdown governor.

**Gets wrong / avoid:** in-memory returns-matrix scale (fine for 750 names daily); its transaction-cost handling is a linear term, far short of our statutory + square-root-impact model — keep costs in our layer; young project, API drift risk. Frozen-constraint note: use it **only inside the equity cross-section** — asset mix stays policy.

## 7. gs-quant — a declarative policy grammar

**Repo:** [goldmansachs/gs-quant](https://github.com/goldmansachs/gs-quant) | [Backtesting docs](https://developer.gs.com/docs/gsquant/pricing-and-risk/backtesting/)

**Dataflow.** Instrument object model; a **context stack** (`PricingContext`/`HistoricalPricingContext`) that makes pricing/risk calls *deferred and batched*; and a **declarative backtesting DSL**: a `Strategy` = initial portfolio + **Triggers** (`PeriodicTrigger`, market-level triggers) + **Actions** (`AddTradeAction`, rebalance/hedge actions), executed by a `GenericEngine`. The strategy is *data describing policy*, not imperative code.

**Gets right (vs v1):** our regime->book-policy mapping (asset mix, leverage rungs, hedge grid 0-150%, tail-sleeve throttle) is currently policy-in-prose/config; the Trigger/Action pattern shows how to encode it as a tiny auditable grammar — "when R crosses bucket boundary with hysteresis, action = move hedge one rung" — which makes the policy layer *itself* backtestable, diffable, and pre-registrable. Deferred/batched computation is also the right mental model for expensive risk recomputes on free infrastructure.

**Gets wrong / avoid:** most value (pricing engines, data) is gated behind a GS institutional API; the OSS layer is a client SDK, not a runnable pipeline. Borrow the DSL shape only.

## 8. OpenBB (~63k stars) — the data-layer pattern

**Repo:** [OpenBB-finance/OpenBB](https://github.com/OpenBB-finance/OpenBB) | [Architecture blog](https://openbb.co/blog/exploring-the-architecture-behind-the-openbb-platform/), [Architecture docs](https://docs.openbb.co/odp/python/developer/architecture_overview)

**Dataflow.** Core routers expose standardized endpoints; each data source is an independent **provider extension** implementing a **TET (Transform-Extract-Transform) pipeline** against **standard data models** (shared pydantic schemas; standardized country/exchange codes). Providers can be added/removed without touching the core; one endpoint, many interchangeable sources.

**Gets right (vs v1):** this is the missing formal shape of our data layer. Each free Indian source (RBI/DBIE, NSE/BSE bhavcopy, AMFI, NSDL FPI, FRED, BIS, MOSPI, CCIL) should be a provider extension: fetch -> validate against a standard schema -> stamp vintage -> land. Benefits for 2026-2040: source failover when a free endpoint breaks or changes format (a *certainty* over 14 years), schema-level tests independent of source quirks, and trivially adding new free sources without touching downstream code.

**Gets wrong / avoid:** no point-in-time/vintage concept in the core platform **[VERIFY — not found in architecture docs]** — we must weld our vintage-stamping into the final Transform; breadth-over-depth culture and commercial Workspace pivot mean we take the pattern, not the dependency.

## 9. freqtrade / FreqAI (~40k stars [VERIFY]) — retraining cadence and adversarial bias CI

**Repo:** [freqtrade/freqtrade](https://github.com/freqtrade/freqtrade) | Docs: [FreqAI](https://www.freqtrade.io/en/stable/freqai/), [Lookahead analysis](https://www.freqtrade.io/en/stable/lookahead-analysis/), [Recursive analysis](https://www.freqtrade.io/en/stable/recursive-analysis/)

**Dataflow.** Strategy objects over a dry-run/live-symmetric bot loop. **FreqAI**: sliding-window retraining where `train_period_days`/`backtest_period_days` define the walk-forward geometry identically in backtest and live; live retraining runs **on a separate thread from inference and trading**; the stated hypothesis is that *retraining from scratch on a window beats online fine-tuning* under regime chaos — all variants configurable.

Two commands matter most: **`lookahead-analysis`** — an adversarial harness that *provokes* lookahead by chaining truncated backtests and diffing indicator values and entry/exit placements against the full backtest (it inspects behavior, not code); **`recursive-analysis`** — detects insufficient warm-up history by measuring indicator-value variance as start dates shift. (Community issue [#11346](https://github.com/freqtrade/freqtrade/issues/11346) shows even these can be evaded — they are a net, not a proof.)

**Gets right (vs v1):** our "no lookahead" is a manifest-discipline promise; freqtrade shows it can also be a **push-button adversarial test run as CI on every candidate signal** — chained-window re-simulation + diff is implementable in a few hundred lines on our stack. Retrain cadence as *declared config shared verbatim between backtest and production* is the right formalization of our half-life re-estimation cadence. Dry-run as a first-class mode (paper-trade a change against live data before capital) maps directly onto how our Stage-2 overlay should earn trust.

**Gets wrong / avoid:** crypto-centric per-pair models; hyperopt culture (mass parameter search with weak multiplicity control); indicator-soup strategies. Take the *rituals* (bias CI, dry-run gate, cadence-as-config), not the strategy layer.

## 10. NautilusTrader — backtest/live parity via a single kernel

**Docs:** [Architecture](https://nautilustrader.io/docs/latest/concepts/architecture/), [Message bus](https://nautilustrader.io/docs/latest/concepts/message_bus/)

**Dataflow.** Rust-native core; one **NautilusKernel** shared by `BacktestEngine` and `LiveNode`; components (data engines, risk engine, execution, Portfolio, Actors/Strategies) communicate over a **MessageBus** (loose coupling, actor-model style) with a central in-memory **Cache**; a **single-threaded core gives deterministic event ordering**, so a backtest is a bit-reproducible replay of the same machinery that trades live.

**Gets right:** the strongest OSS statement of "the research artifact and the production artifact are the same object" — the standard our Stage-1 emitter should meet at daily/weekly cadence (same code produces the historical simulation and today's live portfolio; only the data feed and clock differ). The message-bus pattern also shows how monitoring attaches non-invasively: monitors are just subscribers.

**Gets wrong / avoid:** built for latency-sensitive multi-venue trading; adopting it for a monthly-rebalance cycle-stack book would be a multi-quarter engineering detour with near-zero payoff. Borrow the parity principle and the subscriber-monitoring pattern only.

## 11. PyBroker — bootstrap honesty on metrics

**Repo:** [edtechre/pybroker](https://github.com/edtechre/pybroker) | [Docs](https://www.pybroker.com/en/latest/)

Numba-accelerated engine where **walk-forward analysis is the default evaluation mode** (windows roll forward, prior test data joins training), models register through a small **model registry** with automatic prediction caching, and — the distinctive element — all headline metrics ship with **BCa (bias-corrected accelerated) bootstrap confidence intervals**. **Gets right:** "no metric without an interval" complements our deflated Sharpe: DSR handles multiplicity, bootstrap CIs handle sampling noise; both should appear on every ledger row. **Gets wrong:** single-asset/strategy focus, thin portfolio layer — the pattern is the takeaway.

## 12. LLM-agent frameworks: FinRL, FinGPT, TradingAgents, RD-Agent — treated skeptically

**Repos:** [AI4Finance-Foundation/FinRL](https://github.com/AI4Finance-Foundation/FinRL) (~14k stars [VERIFY exact]), FinGPT, [TauricResearch/TradingAgents](https://github.com/tauricresearch/tradingagents), [microsoft/RD-Agent](https://github.com/microsoft/rd-agent)

**TradingAgents** organizes LLM agents as a firm (analysts -> bull/bear researchers -> trader -> risk team -> portfolio manager) with structured-output decision nodes. Architecturally it contributes two reusable ideas — *role-decomposed analysis with an adversarial (bull/bear) debate step* and *structured-output contracts for LLM decisions* — and nothing else that survives scrutiny. The 2026 evaluation literature is brutal and specific: [The Alpha Illusion](https://arxiv.org/html/2605.16895) (short-window alpha from LLM agents fails on temporal contamination, friction, and researcher degrees of freedom); [Look-Ahead-Bench](https://arxiv.org/pdf/2601.13770) (pretrained LLMs leak memorized future facts even without future documents at inference); [CLQT](https://arxiv.org/html/2606.29771) (look-ahead, survivorship, overfitting, cost neglect, regime blindness "can reverse the sign of reported returns"); and [Summoning the Oracle to Slay It](https://arxiv.org/pdf/2605.24564) shows deliberately leaky oracles posting Sharpe 35 *pass statistical correction tests* — structural guardrails, not statistics, are the only defense. This literature *vindicates our frozen rules* (LLM-generated backtests inadmissible; overlay advisory-only, reduce-only, switchable off) — nothing in it argues for loosening them; notably, even TradingAgents' own changelog shipped an "Alpha Vantage look-ahead filtering" fix in 2026.

**FinRL** is architecturally a three-layer (market environments / agents / applications) RL stack; its lasting contribution is process, not code: the FinRL Contests **reject agents with high estimated probability of backtest overfitting at a 10% significance level** — an admission gate worth copying into any research funnel. FinGPT is a data-and-finetuning pipeline for financial LLMs; for this desk it is only relevant as a reminder that any model pretrained on the open web embeds future knowledge relative to any historical backtest date (contamination is *architectural*, not fixable by prompting).

**RD-Agent(Q)** ([paper](https://arxiv.org/pdf/2505.15155v2), [MSR page](https://www.microsoft.com/en-us/research/publication/rd-agent-quant-a-multi-agent-framework-for-data-centric-factors-and-model-joint-optimization/)) is the serious one: a multi-agent loop — hypothesis generation -> code implementation (Co-STEER) -> execution in a *fixed external harness* (Qlib backtest) -> result interpretation -> next hypothesis — reporting up to 2x returns with 70% fewer factors [their claim, on their benchmark; treat as marketing]. The architectural lesson survives even total skepticism about the numbers: **the agent proposes, a mechanical pre-registered harness disposes**. The agent never grades its own work; every idea pays full validation toll through the same fixed pipeline. That is exactly how Claude should function inside this desk's research process — as a hypothesis/implementation engine whose every trial is forced through our qrun-style harness onto our vintage-stamped data, with every attempt (including failures) auto-logged to the trial ledger so deflated Sharpe stays honest. The failure mode to engineer against: agentic search runs *thousands* of implicit trials; without automatic trial capture, DSR is dead on arrival ([leakage-safe, search-aware assessment](https://arxiv.org/html/2608.27734)).

## 13. Data-layer addendum: ArcticDB

**Repo:** [man-group/ArcticDB](https://github.com/man-group/ArcticDB) | [Site](https://arcticdb.io/)

Man Group's serverless DataFrame database (Python API, C++ engine, object-storage or local-disk backend) with **bitemporal versioning: every write creates a version, enabling as-of point-in-time reads, reproducible research, and historical corrections** — built explicitly for front-office quant research and now co-developed with Bloomberg. This is the industrial-grade version of our vintage-stamped manifests: instead of "manifest says which file was known when," any dataset can be read *as of* any past research date with one API call, making lookahead structurally harder. **Caution:** license is BSL-style, fine for internal desk use but restricts redistribution as a service **[VERIFY exact current license terms]**; and for our data volumes, parquet + a small as-of index may capture 90% of the benefit with zero new dependency — adopt the *bitemporal read API contract* even if we implement it ourselves.

## 14. Cross-cutting synthesis: what the field converged on, and where v1 stands

Across all ten-plus frameworks, five architectural convergences matter for 2026-2040:

1. **Typed contracts between stages** (LEAN Insight/PortfolioTarget; OpenBB standard models; skfolio estimators). v1's stages exist but their interfaces are informal. Formal signal objects carrying *expiry/half-life and confidence* natively encode McLean-Pontiff decay.
2. **Experiments as config + automatic recording** (Qlib qrun/Recorder-MLflow; PyBroker registry). v1's pre-registration and trial ledger are the right idea executed manually; the field shows they should be machine-enforced side effects of running anything.
3. **The deployment loop is itself an object** (Qlib OnlineManager.routine(); FreqAI cadence config; NautilusTrader kernel parity). v1 has cadences in prose; the winners make "retrain schedule + model rotation + who-was-live-when ledger" executable and *backtestable*.
4. **Bias detection as automation, not virtue** (freqtrade lookahead/recursive analysis; skfolio CombinatorialPurgedCV as primitive; FinRL overfit-rejection gate; the 2026 LLM-eval literature's structural-guardrail finding). Discipline that lives in checklists dies over 14 years; discipline that lives in CI does not.
5. **A funnel with cost-ordered tiers** (alphalens tear sheets -> vectorbt sweeps -> event-driven replay -> dry-run -> live). v1 jumps from idea to full backtest; a tiered funnel raises idea throughput for a 2-person desk *while* the trial ledger taxes every tier.

**Anti-patterns confirmed across the survey:** model-zoo maximalism (Qlib's 25 deep nets); mass hyperparameter search without multiplicity accounting (freqtrade hyperopt, vectorbt marketing); engines whose realism outruns their data quality (event-driven microstructure simulation on daily bhavcopy); LLM agents evaluated by their own short-window backtests (entire TradingAgents genre); infrastructure sized for firms of 50 (Nautilus/LEAN engines, Qlib's MongoDB cluster mode) adopted by desks of 2. Our frozen constraints already fence off most of these; the survey's main message is that v1's *statistical* architecture is ahead of the open-source field, while its *software* architecture (interfaces, recording, deployment-loop formalization, data adapters, bias CI) is behind it — and the borrowable list below closes exactly that gap.

### Borrowable ideas
- **Config-as-experiment + automatic recorder: every run (signal test, sleeve refit, full backtest) is a single YAML manifest executed by one command, with params, data vintage hash, metrics, and artifacts auto-logged to an MLflow-style store** [Microsoft Qlib (qrun + QlibRecorder/MLflowExpManager)] -> plugs into: Research process + pre-registration/trial ledger: the ledger stops being a document and becomes the run store itself; deflated-Sharpe trial counts are derived by querying the recorder, not by self-report. **Date:** 2026-09-01

## 0. Executive summary — the meta-findings

Across nine very different firms, the portable material is almost never the signals. It is five process invariants:

1. **The risk/allocation layer is separated from the alpha layer everywhere it works.** Bridgewater (beta vs alpha separation), Norges/GIC (reference/policy/active split), pod shops (central risk vs pod alpha). Your frozen "asset mix is policy, never optimized" rule is the institutional consensus, not a quirk. The improvable part is *measuring each layer's contribution separately* (Norges/GIC do this publicly, annually).
2. **Signal lifecycle is managed like manufacturing, not like discovery.** AQR publishes decay haircuts; Marshall Wace scores every contributor's live hit-rate; Millennium terminates pods on hard drawdown rules; McLean–Pontiff (already frozen into v1) is the academic version. The firms differ on *how* signals die (statistical decay evidence vs raw PnL stops) — that choice matters and is analyzed below.
3. **Costs and capacity are researched as hard as alpha.** Renaissance's edge was substantially slippage modeling (Zuckerman); AQR published the definitive trading-cost paper on its own $1trn of live trades; Man AHL applied ML to execution *before* alpha. A 2-person desk with 22.3bps round-trip cash costs in India should treat the cost model as a first-class research object with its own backlog and decay ledger.
4. **Human judgment enters through scored, auditable channels — or it contaminates.** Marshall Wace systematized outside human opinion into a track-recorded feed (TOPS). Bridgewater claims believability-weighted governance; Copeland's reporting says the reality was founder override [REPORTED/disputed]. Renaissance's early lesson (Berlekamp era) was to *remove* ad-hoc human overrides. Your Stage 2 advisory-only + veto + trial-ledger design is directionally right; the missing piece is *scoring* the overlay like a TOPS contributor.
5. **ML has a settled division of labor at the credible shops.** AQR (Israel–Kelly–Moskowitz) and Man AHL agree in print: ML earns its keep first in execution, cost estimation, covariance, and signal *combination* — not in low-sample macro prediction. This maps a clean charter for how Claude/ML is used inside v1.

What does **not** port: pod-shop headcount arbitrage, Two Sigma/RenTech-scale data infrastructure spend, Bridgewater's institutional sales machine, and anything requiring proprietary data. What ports surprisingly well: governance rituals, lifecycle rules, netting/craftsmanship, and the policy/active decomposition — all of which are cheap and mostly require discipline, not money.

## 1. Grinold & Kahn, *Active Portfolio Management*

### Pipeline in words
Raw signal → standardized **score** (zero mean, unit sd, cross-sectionally) → **alpha = volatility × IC × score** (Grinold's 1994 "rule of thumb"; volatility = residual vol, IC = correlation of scores with subsequent residual returns) → alpha refinement (scale, trim outliers, neutralize benchmark/factor exposure) → mean-variance optimization against **active** risk with a risk-aversion parameter → implementation → **ex-post performance analysis measuring realized IC** → back to signal research. Governing identity: **IR = IC × sqrt(BR)** where BR = number of *independent* bets per year; extended by Clarke, de Silva & Thorley (2002) to **IR = IC × sqrt(BR) × TC**, where TC (transfer coefficient) is the correlation between intended alphas and actual active weights — with realistic constraints TC can fall to ~0.3. Value added ≈ IR² / (4λ) at the optimum [VERIFY exact form]. Breadth is NOT the number of names: correlated bets (all names loading on the same factor) collapse effective breadth — see the "how to calculate breadth" literature (Buckle; FLAM Redux).

Sources: [Grinold, "Alpha is Volatility Times IC Times Score" (Semantic Scholar)](https://www.semanticscholar.org/paper/Alpha-is-Volatility-Times-IC-Times-Score-Grinold/2a4f17ec623c0f299e52ada43065a9152449fefc); [MSCI Barra, "Converting Scores into Alphas"](https://www.msci.com/documents/10199/1637567/PI_Converting_Scores_Into_Alphas.pdf/3347ac6c-8ece-43cb-a6d6-ec2e84884090?version=1.0); [Clarke, de Silva, Thorley, "Portfolio Constraints and the Fundamental Law" (FAJ 2002)](https://www.tandfonline.com/doi/abs/10.2469/faj.v58.n5.2468); [FLAM Redux (ScienceDirect)](https://www.sciencedirect.com/science/article/pii/S0927539817300543); [APM full text (1999 ed.)](http://cms.dm.uba.ar/academico/materias/2docuat2016/analisis_cuantitativo_en_finanzas/Richard%20Grinold,%20Ronald%20Kahn-Active%20Portfolio%20Management_%20A%20Quantitative%20Approach%20for%20Producing%20Superior%20Returns%20and%20Controlling%20Risk-McGraw-Hill%20(1999).pdf); [Northfield capacity note applying FLAM](https://www.northinfo.com/documents/266.pdf).

### Where v1 violates or lacks
1. **No breadth accounting, and breadth lives in the wrong place mentally.** The 16-variable regime ladder → R is essentially ONE bet per rebalance cadence (call it 12-52 independent-ish bets/yr at best, fewer after autocorrelation of regimes). The 750/500-name factor cross-section is where nearly all of the desk's breadth is. IR = IC×sqrt(BR)×TC says a mediocre-IC cross-sectional engine will dominate a brilliant-IC macro timing engine on realized IR. v1's fixed block budgets are fine as risk policy, but research hours and monitoring sophistication are currently skewed toward the low-breadth module.
2. **No alpha-magnitude discipline.** v1 goes score → rank → candidates. Ranks destroy magnitude and make the "published-alpha decay haircut" unanchored. Grinold's rule (alpha = residual vol × IC × score, with IC set conservatively from a pre-registered grid, e.g. {0.02, 0.05, 0.10} — grids, not magic numbers) gives self-shrinking alphas: if IC≈0 the alphas are ≈0. Trim extreme alphas (book suggests trimming at roughly 3× the alpha scale [VERIFY exact threshold]) before Stage 3 sizing.
3. **TC is unmeasured.** v1's drift bands, 5-6% entries, days-to-build caps, turnover caps, and drawdown-cushion multipliers all sit between alpha and weights, and nothing measures how much signal survives. A monthly TC number per book (rank-corr of intended alpha vs realized active weight) is nearly free to compute and tells you whether to fix signals (IC) or plumbing (TC). Expect the Conservative book's TC to be structurally low; that is a design input, not a failure.

### Integration points
- Return engine, scoring step: insert alpha-conversion after sleeve scoring, before ranking.
- Monitoring: add realized-IC-per-sleeve and TC-per-book to the decay ledger cadence.
- Research process: annual "breadth budget" ritual — list every independent bet the system takes per year; prioritize research by marginal breadth × attainable IC.

## 2. López de Prado, *Advances in Financial Machine Learning*

### Pipeline in words
Two decompositions. **(a) The organizational "production chain" (strategy factory):** data curators → feature analysts → strategists → backtesting specialists → deployment team → portfolio oversight, with oversight running the strategy lifecycle: embargo/paper trading → graduation to small allocation → scaling by realized performance → decay watch → decommission. Individual "Platonic" quants failing alone is the anti-pattern; assembly-line stations with hand-off artifacts is the pattern. **(b) The methodological chain:** structured sampling (event-based bars) → labeling (triple-barrier: profit-take/stop-loss/time barriers) → **sample weights by uniqueness** (overlapping labels are not IID; weight by average uniqueness, sequential bootstrap) → stationarity transforms (fractional differentiation) → ensemble learners → **purged & embargoed K-fold CV** → feature importance (MDI/MDA/SFI) before backtesting → **CPCV** (combinatorial purged CV generating many backtest paths, not one) → **bet sizing** from predicted probabilities (size = f(P[label]), averaging across concurrently active bets, discretized to limit churn [VERIFY details]) → backtest statistics → **PBO** (probability of backtest overfitting, via CSCV) and **deflated Sharpe**. Meta-labeling: the primary model (which can be a simple rule or a human/quant model) decides the **side**; a secondary ML model is trained on the primary model's outcomes to predict P(success), which sets the **size** — improving precision without touching recall, and keeping the primary model interpretable.

Sources: [Wikipedia, Meta-Labeling](https://en.wikipedia.org/wiki/Meta-Labeling); [Hudson & Thames, "Does Meta-Labeling Add to Signal Efficacy?"](https://hudsonthames.org/wp-content/uploads/2022/04/Does-Meta-Labeling-Add-to-Signal-Efficacy.pdf); [Wikipedia, Purged cross-validation](https://en.wikipedia.org/wiki/Purged_cross-validation); [Backtest overfitting comparison study (ScienceDirect)](https://www.sciencedirect.com/science/article/abs/pii/S0950705124011110) — CPCV shows lower PBO and superior DSR than alternatives; [Quantitative Finance review of AFML](https://www.tandfonline.com/doi/full/10.1080/14697688.2019.1703030) — confirms the six-role production chain; [Reasonable Deviations chapter notes](https://reasonabledeviations.com/notes/adv_fin_ml/).

### Where v1 violates or lacks
1. **No CPCV/PBO station.** v1 has purged/embargoed CV and deflated Sharpe with trial counts (good — already ahead of most). But single-path backtests remain the evidence unit. CPCV produces a distribution of paths and a PBO number per candidate; the trial ledger should require PBO < a pre-registered threshold (grid: {0.1, 0.25, 0.5}) for graduation. This is the strongest available defense for a desk that assumes McLean-Pontiff decay.
2. **Overlapping-label sample weights are missing.** Cycle/regime labels at monthly-ish horizons overlap massively; any estimation on them (IC estimates, factor half-lives, credit-cycle state fitting) silently overstates sample size. Weight observations by uniqueness before computing ICs, half-lives, and deflated Sharpe inputs.
3. **Meta-labeling is the formally correct shape for Stage 2.** Frozen rules: Stage 1 emits the complete portfolio; Stage 2 is advisory, reduce-only, switchable off. Meta-labeling fits exactly: Stage 1 = primary model (side + full base size); a meta-model outputs confidence in [0,1] that multiplies size — mathematically incapable of adding exposure, hence natively reduce-only; switch off = multiplier fixed at 1. This converts Stage 2 from "AI+human vibes, clamped" into a measurable, backtestable, pre-registerable component — while the human veto stays on top.
4. **The strategy factory maps onto a 2-person desk as stations, not people.** Data curation, feature analysis, strategy assembly, backtest validation, deployment, oversight become pipeline stages with hand-off artifacts (vintage-stamped manifests → feature store → candidate spec → CPCV/PBO report → deployment config → oversight ledger). Claude runs stations under station-specific checklists; the principal is oversight. This is the research-process improvement the task asked about: signals get discovered at station 2, validated at station 4, retired at station 6, and no station may skip ahead.

### Integration points
- Research process: CPCV+PBO as a mandatory validation station; results logged in the pre-registration/trial ledger.
- Risk engine estimation standards: uniqueness weights wherever overlapping labels feed estimators.
- Stage 2: meta-labeling sizing multiplier as the first "proven" pathway from advisory to systematic (still reduce-only).
- Data layer: the existing manifests become station-1 artifacts of the factory; add a point-in-time feature store as the curator/analyst hand-off.

## 3. Robert Carver, *Systematic Trading* and *Advanced Futures Trading Strategies*

### Pipeline in words
*Systematic Trading:* instruments → **trading rules** each emitting a raw forecast, vol-standardized so it is scale-free → **forecast scaling**: scalar = 10 / E|raw forecast|, so every rule's forecast has expected absolute value 10; **cap at ±20** (risk control; extreme forecasts are rare, unreliable, and coincide with abnormal vol) → **forecast combination**: weighted average using *handcrafted* (rule-based, not optimized) weights, times a forecast diversification multiplier → **volatility targeting**: choose an annualized cash vol target from tolerance for loss (his rule of thumb ties it to roughly half the expected Sharpe [VERIFY]); position = (combined forecast / 10) × volatility scalar (target vol / instrument vol) → **instrument weights × instrument diversification multiplier (IDM)** — scales gross up so the diversified portfolio actually hits target vol; IDM capped around 2.5 [VERIFY cap] → **position inertia / buffering**: compute optimal position, trade only when the current position drifts outside ~±10% of optimal → execution. Overarching philosophy: **no fitted parameters** — every number is either a rule, an estimated scalar with huge samples (forecast scalars, vol), or a handcrafted weight; plus a **"speed limit"**: expected trading cost per instrument budgeted in Sharpe-ratio units (~0.13 SR/yr max in his framework [VERIFY exact figure]) — a rule too costly for an instrument is simply not traded there. *Advanced Futures Trading Strategies:* the same machine presented as an ordered stack of ~30 strategies, each strategy a minimal increment on the previous (buy-and-hold with vol scaling → trend → carry → ... → dynamic optimization for small capital), i.e., pipeline-as-curriculum with each block independently justified.

Sources: [Systematic Trading chapter summary (awesome-quant-ai)](https://github.com/leoncuhk/awesome-quant-ai/blob/main/book/Systematic%20Trading%20A%20unique%20new%20method%20for%20designing%20trading%20and%20investing%20systems.md) — confirms scalar = 10 / avg abs forecast, cap ±20; [CXO Advisory notes](https://www.cxoadvisory.com/big-ideas/a-few-notes-on-systematic-trading/); [Carver's blog on estimated forecast scalars](https://qoppac.blogspot.com/2016/01/pysystemtrader-estimated-forecast.html); [7 Circles ch. 3 summary](https://the7circles.uk/systematic-trading-3-frameworks-and-forecasts/).

### Where v1 violates or lacks
1. **No common forecast currency across sleeves.** v1's five factor sleeves each carry their own haircut but their scores live on different scales, so sleeve combination weights are not comparable and the decay haircut is applied to incommensurable objects. Carver's fix is exactly the no-magic-numbers estimation standard: scale every sleeve forecast to E|f| = 10 (an estimated scalar), cap at 20, then combine with handcrafted weights. Note v1's regime score R in [-1,1] with fixed block budgets is already Carver-shaped; the equity return engine is not.
2. **Leverage caps are not vol targets.** v1 expresses book risk as gross leverage ≤1.5x with bucket-dependent floors. Carver (and the drawdown governor's own logic) says the primitive is a cash **volatility target** per book; leverage is the output, not the policy. A vol-target restatement makes the drawdown governor computable ex ante (target vol × worst-case multiple vs the 30-35% ceiling) and makes positions self-adjust when Indian equity vol regimes shift. Asset mix stays policy (frozen); this is about how the equity sleeve's gross is set within policy.
3. **Costs budgeted in the wrong unit.** v1 has excellent cost measurement (22.3bps cash vs 5.7bps futures, sqrt impact) and turnover caps, but caps are quantity limits, not value limits. Carver's speed limit prices each sleeve's turnover in SR units: a short-term reversal sleeve that spends 0.4 SR/yr in Indian cash-delivery costs fails admission for the Conservative book regardless of its gross alpha. This turns the cost model into a sleeve-admission rule per book — which the three-book structure begs for.
4. (Confirmation, not violation) v1's ~10% drift band ≈ Carver buffering — but buffer around the **optimal** position, not around the last trade, so the band tracks the signal rather than history.

### Integration points
- Return engine: forecast-scaling layer between sleeve scoring and combination; handcrafted sleeve weights documented as rules.
- Book policy: restate the leverage grid as per-book vol targets with leverage as derived quantity (grid of targets, pre-registered).
- Execution/costs: per-sleeve, per-book SR-unit cost budget; sleeve admission matrix (e.g., reversal admissible in Aggressive via futures-hedged implementation only).

## 4. Rishi Narang, *Inside the Black Box*

### Pipeline in words
The canonical module diagram (p.19): **Data** and **Research** feed everything; three parallel models — **Alpha model** (what will make money; theory-driven or data-driven), **Risk model** (what exposures to limit *regardless of alpha*: size limits, factor exposure limits), **Transaction cost model** (what it costs to change positions) — all three are inputs to the **Portfolio construction model** (rule-based or optimized), which hands targets to the **Execution model** (order scheduling, aggressiveness, venue), with a feedback loop from execution back to construction. The load-bearing insight: **alpha and risk must be separate models** because a single conflated objective lets return-seeking silently override risk limits; the risk model exists to say "no" on grounds the alpha model cannot argue with. Third edition (2024) extends to ML alphas and alt data without changing the module boundaries.

Sources: [Inside the Black Box 2nd ed. (O'Reilly)](https://www.oreilly.com/library/view/inside-the-black/9781118416990/); [book sample PDF with the framework](https://content.e-bookshelf.de/media/reading/L-24402424-11c92b354b.pdf); [3rd ed. overview (Google Books)](https://books.google.com/books/about/Inside_the_Black_Box.html?id=NuoAzwEACAAJ).

### Where v1 violates or lacks
1. **v1 has a regime engine, not a (cross-sectional) risk model.** Narang's risk model constrains unintended exposures of the *portfolio the alpha model wants*: sector, size, beta, single-name concentration. v1's "risk engine" is macro timing (top-down policy) — legitimate and separate — but the equity cross-section goes score → rank → size with Ledoit-Wolf used for risk budgeting only, and nothing formally caps unintended factor bets. A ranked momentum book in India will routinely be a concentrated sector bet. Add a thin exposure-limit layer (sector/size/beta bands, grids not magic numbers) inside Stage 3 — it touches the equity cross-section only, so it is frozen-compliant.
2. **The cost model must be an input to construction, not a post-hoc cap.** v1's turnover caps and days-to-build caps trim after the fact. Narang's architecture puts expected cost inside the sizing decision (v1's "buildable-within-half-life" term is halfway there); complete it by netting expected round-trip cost against Grinold-scaled alpha before ranking, so cheap-to-trade alpha outranks equal gross alpha that is expensive to realize.
3. **Execution is not a module in v1.** Costs are modeled; *scheduling* is not. Narang separates the execution model (participation rates, urgency, order type, futures-vs-cash choice for hedges) with a feedback loop to construction. For this desk: a deterministic execution scheduler (e.g., spread entries over N days at ≤X% ADV, hedge adjustments via index futures first) plus a slippage ledger feeding back into the cost model's impact coefficients — automatable by Claude, and the feedback loop is one of the "missing cadences" the task flags.

### Integration points
- Stage 3: exposure-limit layer (risk model proper) alongside the existing sizing rules; cost-netted alpha before ranking.
- New module between Stage 3 and the market: execution scheduler + slippage ledger; monthly recalibration of the sqrt-impact coefficient from own fills (free data: your own trades).

## 5. Antti Ilmanen, *Expected Returns*

### Pipeline in words
Not an implementation pipeline but an **input discipline**: every expected return is built **ex ante** from observable yields and carry plus growth/roll minus expected losses — never from trailing realized returns — and every estimate is triangulated through **multiple lenses**: (1) long historical averages, (2) theory (rational risk premia AND behavioral/supply-demand explanations), (3) current market pricing (forward-looking yields/valuations), plus surveys. Returns are organized in a cube [VERIFY exact "cube" framing]: asset-class premia × style premia (**value, momentum, carry, defensive** — the four with the most consistent cross-context evidence) × underlying macro risk factors (growth, inflation, liquidity, volatility). Every premium is understood as compensation for *when it loses* — bad-times covariance, not variance, prices assets; e.g., trend-following was profitable in 13 of the 15 worst equity months over 25 years, while carry-type premia crash in bad times.

Sources: [Ilmanen, "Expected Returns on Major Asset Classes" (CFA Institute RF)](https://rpc.cfainstitute.org/sites/default/files/-/media/documents/book/rf-publication/2012/rf-v2012-n1-1-pdf.PDF); [Rational Reminder ep. 202 summary](https://rationalreminder.ca/podcast/202).

### Where v1 violates or lacks
1. **v1 has no ex-ante expected-return layer at the book level.** The valuation/sentiment block presumably scores z-scores of valuations for regime purposes, but nothing produces "the debt sleeve's expected real return is X (from RBI/CCIL yields), equity ERP is Y (earnings yield minus real yield), gold's expected return is Z (real-rate framing)". Those numbers should discipline the haircut-Kelly inputs and the asset-mix *policy reviews* (policy stays policy — this informs the humans who set it, quarterly).
2. **Bad-times covariance audit.** The drawdown constraint is binding, and several v1 sleeves plus the India books' structural exposures (credit-cycle tilts, small-cap ranks 501-750 in Aggressive, illiquidity) are all carry-like — they lose together in the same bad state. An Ilmanen-style classification of every sleeve/block as "smooth carry-like" vs "crisis-convex trend-like" tells you whether the stack's diversification is real or cosmetic precisely in the >20% drawdown episodes the governor is graded on.

### Integration points
- Risk engine, valuation block: replace/augment trailing z-scores with ex-ante yield spreads from free sources (RBI/DBIE, CCIL, FRED).
- Governance ritual: quarterly capital-market-assumptions memo (three lenses per sleeve) feeding Kelly numerators and the human asset-mix policy review.
- Monitoring: tag each sleeve carry-like/convex-like; report the stack's net bad-times beta alongside the drawdown governor.

## 6. Chincarini & Kim, *Quantitative Equity Portfolio Management*

### Pipeline in words
The z-score/factor assembly line: define universe and **benchmark** → select factors (fundamental, technical, economic) with economic rationale → point-in-time data hygiene → per-factor exposures: winsorize, then standardize into **z-scores, typically within sector/industry** → **aggregate z-score** = weighted sum of factor z-scores (weights from rules or historical factor-return regressions) → expected returns via the Z-score model or a full factor model → portfolio construction under benchmark-relative constraints (**tracking error** budget, sector/size neutrality) via screening or optimization → tax/cost-aware rebalancing → **ex-post factor attribution** closing the loop. Built on seven tenets, the first three being: markets are mostly efficient; pure arbitrage does not exist; quantitative analysis creates *statistical* arbitrage opportunities (remaining tenets from memory include: quant analysis must be disciplined to avoid data mining, and combining factors judiciously beats single factors [VERIFY exact list]).

Sources: [CFA Institute review of QEPM](https://rpc.cfainstitute.org/research/financial-analysts-journal/2008/quantitative-equity-portfolio-management) — confirms the first three tenets; [QEPM 2nd ed. (Google Books)](https://books.google.com/books/about/Quantitative_Equity_Portfolio_Management.html?id=K-uLEAAAQBAJ). Z-score pipeline steps from memory of the text [VERIFY step details].

### Where v1 violates or lacks
1. **No sector-relative standardization.** Scoring across the whole NIFTY 750/500 lets value and momentum degenerate into sector rotation (in India: perennial IT-vs-financials-vs-PSU tilts). Standardizing z-scores within sectors (or offering both flavors per sleeve, chosen by pre-registered rule) isolates stock selection from sector bets — and pairs with the Narang exposure-limit layer.
2. **No explicit benchmark per book in the return engine.** The drawdown constraint is benchmark-relative ("never materially worse than Nifty 50 in >20% drawdowns") but construction is benchmark-free. QEPM says: define the benchmark, measure active weights and ex-ante tracking error against it (Ledoit-Wolf is already computed), even if you do not optimize to it. Otherwise the binding constraint is being monitored on a quantity the engine never sees.
3. **Attribution loop missing.** QEPM's endpoint — factor-level performance attribution — is the natural automated feeder for the decay ledger: realized factor returns per sleeve per book each month, so decay is detected from *your own* portfolio's attribution, not only from published-anomaly monitoring.

### Integration points
- Return engine: sector-relative z-score option per sleeve; aggregate-score construction documented QEPM-style.
- Stage 3 / monitoring: ex-ante TE vs Nifty 50 (Conservative/Moderate) reported next to the drawdown governor; monthly factor attribution auto-written to the decay ledger.

## 7. Ernie Chan, *Quantitative Trading* / *Machine Trading*

### Pipeline in words
The independent-trader production loop: idea sourcing (mostly borrowed, then modified) → simple backtest with hygiene (survivorship-free data, transaction costs, no lookahead) → **walk-forward**: fit on rolling window, trade the next period out-of-sample, concatenate the out-of-sample segments as the only performance record — making validation an *ongoing production process*, not a one-time gate → sizing via **Kelly, in practice half-Kelly** (fat tails, estimation error) → live paper trading → small live capital → **capacity awareness**: linear/cross-sectional strategies degrade with size as sqrt-impact eats alpha, so capacity is a first-class strategy attribute → continuous monitoring with a preset retirement rule (e.g., cut or kill when live drawdown materially exceeds the backtest's worst [VERIFY exact rule]). *Machine Trading* adds Conditional Parameter Optimization — re-fitting strategy parameters conditioned on market regime features.

Sources: [Quantitative Trading 2nd ed. (O'Reilly)](https://www.oreilly.com/library/view/quantitative-trading-2nd/9781119800064/) — confirms Kelly treatment and Conditional Parameter Optimization; capacity and retirement details from memory of the 1st/2nd editions [VERIFY].

### Where v1 violates or lacks
1. **Capacity is not modeled per book, and it is THIS desk's binding design constraint.** Conservative at Rs 10,000-25,000cr inside ranks 1-500 of Indian equities is enormous relative to ADV outside the top ~150 names. Chan's discipline: compute each sleeve's capacity (from ADV, participation caps, sqrt impact, holding half-life) and make sleeve admissibility per book a function of it — short-term reversal is almost certainly uninvestable for Conservative and marginal for Moderate; that should be a pre-registered rule, not a discovery in the live decay ledger.
2. **Walk-forward as the standing evidence format.** v1's CV standards are strong for *research*; Chan's point is that the *production* record should be a continuously extended out-of-sample concatenation — which dovetails with the pre-registration ledger: every deployed sleeve accrues a walk-forward track from its registration date, and that track (not re-run backtests) is what the deflated Sharpe monitors.
3. Half-Kelly: v1's haircut-Kelly already complies — keep it. CPO is attractive but collides with the frozen no-fitted-regime-switching rule; only admissible if conditioning uses the existing regime buckets with grid parameters, never fitted transitions.

## Cross-book synthesis: the canonical order and v1's gaps

All seven converge on one skeleton: **Data (point-in-time) → Alpha/forecast model → Risk model → Cost model → Portfolio construction → Execution → Attribution/monitoring → Research loop back to data** — with Narang naming the boxes, Grinold & Kahn pricing the whole chain (IC, BR, TC), Carver specifying the units inside the boxes (forecast currency, vol targets, cost speed limits), López de Prado industrializing the research loop (factory stations, CPCV/PBO, meta-labeling), Ilmanen disciplining the inputs (ex-ante, three lenses, bad-times covariance), Chincarini & Kim giving the equity-specific z-score recipe with benchmark and attribution, and Chan supplying the production-mode validation (walk-forward) and capacity realism.

**v1 scorecard against the skeleton:** Data layer: strong (vintage manifests) — add a feature store as the factory hand-off. Alpha model: present but lacks a common forecast currency, alpha-magnitude conversion, and sector-relative scoring. Risk model: macro policy engine is strong; the *cross-sectional* risk model (unintended exposures, benchmark TE) is the biggest missing box. Cost model: strong measurement; wrong unit (quantities not SR) and wrong position (post-hoc, not input). Construction: sophisticated sizing; missing exposure limits and cost-netted alphas. Execution: missing as a module (no scheduler, no slippage feedback). Monitoring: strong (governor, decay ledger, DSR); missing realized IC, TC, factor attribution, capacity utilization. Research loop: strong standards; missing CPCV/PBO station, uniqueness weights, breadth budgeting, and the factory-station formalization that lets Claude safely run most of it — which is precisely the leverage a 2-person desk needs for 2026-2040.

Priority order for a desk that assumes edge decay and AI-saturated markets: (1) factory stations + CPCV/PBO (protects the research process itself — the only durable edge), (2) TC/IC/attribution monitoring (tells you what is actually decaying), (3) common forecast currency + cost-in-SR admission (makes the three books internally consistent), (4) cross-sectional risk model + execution scheduler (protects the binding drawdown constraint and capacity), (5) meta-labeling Stage-2 and ex-ante return dashboard (upgrades, not repairs).

Caution: CPCV on 15-25 years of Indian monthly data yields few truly independent paths for slow signals; purging plus embargo shrinks effective samples further, so thresholds must be set expecting wide PBO confidence bands.
- **Weight all estimations that use overlapping labels (IC estimates, sleeve half-lives, regime-block calibrations) by sample uniqueness, since monthly-horizon cycle labels overlap heavily and overstate effective sample size.** [Lopez de Prado, AFML ch. 4 (sample weights, average uniqueness, sequential bootstrap)] -> plugs into: Estimation-standards layer of the risk engine and the half-life re-estimation job in monitoring; a shared utility in the data/feature layer.. Why 2026-2040: Every downstream discipline (deflated Sharpe trial counts, hysteresis triggers, no-fitted-regime rules) silently depends on honest effective sample sizes; uniqueness weighting keeps the desk's own statistics from flattering it.. Caution: Uniqueness weighting shrinks already-small Indian free-data samples further; some sleeves will become formally 'unknowable', which is the correct but uncomfortable answer.
- **Give every sleeve a common forecast currency: vol-standardize raw sleeve scores, estimate a scalar so expected absolute forecast = 10, cap at +/-20, then combine sleeves with handcrafted (rule-based, never optimized) weights.** [Robert Carver, Systematic Trading (forecast scalar = 10 / avg abs forecast; cap 20; handcrafted weights)] -> plugs into: Return engine, a forecast-combination layer between per-sleeve scoring and the Grinold alpha conversion; sleeve weights documented as rules in the pre-registration ledger.. Why 2026-2040: Makes the five sleeves commensurable so combination weights mean what they say, caps the influence of any one sleeve's extreme reading (exactly when models are least reliable), and complies natively with the no-magic-numbers standard since scalars are estimated and weights are rules.. Caution: The cap at 20 deliberately throws away tail conviction; if a sleeve's edge genuinely lives in extremes (short-term reversal in stress), capping plus combination can neuter it - test capped vs uncapped in the CPCV station before adopting per sleeve.
- **Budget trading costs in Sharpe-ratio units per sleeve per book ('speed limit'): estimate each sleeve's annual cost drag in SR terms under each book's instruments and turnover, and make sleeve admission per book conditional on the cost budget.** [Robert Carver, Systematic Trading / Advanced Futures Trading Strategies (cost speed limit, approx 0.13 SR/yr per instrument [VERIFY exact figure])] -> plugs into: Execution/costs block feeding a sleeve-admission matrix per book, decided at pre-registration time; uses the existing 22.3bps cash vs 5.7bps futures figures and sqrt-impact model.. Why 2026-2040: Converts India's high statutory cash-delivery costs from an after-the-fact drag into a design-time filter: it will formally exclude fast sleeves (short-term reversal) from Conservative and force cheap implementations (futures overlays) where they exist - decisions currently made implicitly.. Caution: Cost-in-SR requires an assumed gross SR per sleeve, which is exactly the number most subject to decay; use the haircut (post-decay) SR, or the speed limit will admit sleeves on stale published performance.
- **Split out an execution scheduler as its own module with a feedback loop: deterministic order scheduling (spread entries over N days at max participation rates, futures-first for hedge changes) plus a slippage ledger that recalibrates the sqrt-impact coefficient from the desk's own fills monthly.** [Rishi Narang, Inside the Black Box (execution model as a separate box with feedback to portfolio construction)] -> plugs into: New module between Stage 3 output and the market; slippage ledger feeds the cost model and the days-to-build caps; fully automatable by Claude.. Why 2026-2040: The desk's own fills are the only free, uncontaminated, India-specific impact data in existence; the feedback loop makes the cost model self-improving as book sizes grow toward the Conservative mandate where impact dominates alpha.. Caution: Own-fill samples are small and endogenous (you only observe impact where you chose to trade); recalibrate with shrinkage toward the prior coefficient and never let a few benign months loosen participation caps.
- **Add a thin cross-sectional risk model inside Stage 3: sector/size/beta exposure bands (grids, not point values) and ex-ante tracking error vs Nifty 50 computed from the existing Ledoit-Wolf covariance, constraining the equity portfolio the sleeves want to hold.** [Rishi Narang (alpha and risk must be separate models); Chincarini & Kim, QEPM (benchmark-relative construction, sector-relative z-scores)] -> plugs into: Stage 3 construction, after sizing and before final weights - equity cross-section only, so frozen-compliant; ex-ante TE reported next to the drawdown governor in monitoring.. Why 2026-2040: The binding constraint is benchmark-relative (never materially worse than Nifty 50 in deep drawdowns), yet no module currently sees benchmark-relative risk; this closes that gap and stops momentum/value ranks from degenerating into concentrated Indian sector bets that blow the governor.. Caution: Exposure bands cost TC and expected alpha (Clarke-de Silva-Thorley's own result); set bands wide, pre-register them, and track the TC monitor to price what the risk model is charging.
- **Build a quarterly ex-ante expected-returns dashboard through Ilmanen's three lenses (history, theory, current yields): real yields for the debt sleeve from RBI/CCIL, equity ERP from earnings yield minus real yield, gold via real-rate framing, plus a carry-like vs crisis-convex tag on every sleeve.** [Antti Ilmanen, Expected Returns (building blocks, multiple lenses, bad-times covariance)] -> plugs into: Risk-engine valuation block inputs and haircut-Kelly numerators; quarterly governance ritual informing the humans who set asset-mix policy (policy itself stays frozen).. Why 2026-2040: Ex-ante yields are the only expected-return estimates that do not decay the way published anomalies do, and the bad-times tagging directly audits whether the stack's diversification survives the >20% drawdown episodes the governor is graded on.. Caution: Ex-ante frameworks were persistently early in 2010s equity markets; use the dashboard to set magnitudes and Kelly inputs, never as a standalone timing signal, or it becomes a second unpriced valuation-timing bet.
- **Run a formal capacity audit per sleeve per book (ADV-based buildable size under participation caps, sqrt impact, and holding half-life), making capacity a pre-registered admission attribute - and adopt walk-forward concatenation from each sleeve's registration date as its standing live evidence record.** [Ernie Chan, Quantitative Trading / Machine Trading (capacity, walk-forward as production process, half-Kelly)] -> plugs into: Pre-registration ledger (capacity fields per sleeve per book) plus monitoring (the deflated-Sharpe monitor consumes the accruing walk-forward track, not re-run backtests).. Why 2026-2040: Conservative at Rs 10,000-25,000cr in ranks 1-500 of Indian equities makes capacity, not alpha, the binding design constraint; auditing it up front prevents deploying sleeves whose paper edge is physically unbuildable, and the walk-forward record is the only evidence that stays clean as AI-generated backtests become inadmissible noise.. Caution: Capacity estimates inherit the sqrt-impact model's error and Indian ADV regime shifts; re-audit when book AUM or market microstructure (e.g., T+0 settlement changes) moves materially, with hysteresis to avoid churning admissions.

# Systematic Investing 2026–2040: What Changes, What Doesn't, and What This Desk's Pipeline Must Include

Scope: evidence on (1) alpha decay acceleration, (2) fund LLM/agent deployment, (3) regime instability and adaptive estimation, (4) India market structure, (5) signal-death operations, (6) the case for staying slow — synthesized into design requirements for pipeline v1.

## 1. Alpha decay is accelerating and crowding cycles are shortening — but not uniformly

**The baseline is well-established and replicated.** [McLean & Pontiff](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2156623) remains the anchor: across 97 published predictors, returns are **26% lower out-of-sample and 58% lower post-publication**. [Falck et al. extensions to 72 factors](https://arxiv.org/pdf/2209.13623) find publication year explains ~30% of Sharpe decay variance — later-published factors decay faster.

**New 2025 evidence says decay itself is accelerating.** The arXiv paper ["Not All Factors Crowd Equally: Modeling, Measuring, and Trading on Alpha Decay"](https://arxiv.org/html/2512.11913v1) finds: (a) crowding **accelerated post-2015** — a decay model trained on 1995–2015 over-predicts remaining alpha (0.30 predicted vs 0.15 realized); (b) residual alpha correlates negatively with factor-ETF volume 2013–2024; (c) signals lose roughly **5–10% of effectiveness per year**, faster under stress; and critically (d) **decay is heterogeneous by signal type**: "mechanical" factors with unambiguous recipes (momentum, reversal) decay on schedule, while "judgment" factors admitting multiple interpretations (value) decay slower and less predictably. [Bowles et al., "Anomaly Time" (Journal of Finance 2024)](https://onlinelibrary.wiley.com/doi/10.1111/jofi.13372?af=R) adds a timing dimension: anomaly returns are now **concentrated in the first month after the information release date** — the race is to information-event alignment, not just factor membership.

**Crowding cycles are shortening and unwinds are getting faster.** The [February–March 2025 quant unwind](https://www.hedgeweek.com/quant-hedge-funds-see-worst-drawdown-since-october-as-crowded-trades-unwind/) saw hedge funds [de-gross single-stock positions at the fastest rate in two years](https://site.financialmodelingprep.com/market-news/hedge-funds-unwind-positions-at-record-levels-amid-market-turbulence) from record 2.9x leverage, with net leverage collapsing to the 8th percentile within weeks — a positioning cycle that used to take quarters now completes in days. [Resonanz Capital's 2025 quant-unwind post-mortem](https://resonanzcapital.com/insights/crowding-deleveraging-a-manual-for-the-next-quant-unwind) treats crowding/deleveraging monitoring as a core allocator diligence item now.

**The AI-specific mechanism.** A 2026 line of work ([AI-Driven Alpha Decay: Algorithmic Homogenization, Reflexive Signal Erosion](https://arxiv.org/html/2605.23905); [Representation Homogeneity and Systemic Instability](https://arxiv.org/pdf/2604.22818)) argues that agents built on similar foundation models, trained on similar corpora, converge on similar representations and therefore **commit similar forecast errors, especially under stress** — accelerating erosion of consensus signals while leaving idiosyncratic-data signals relatively intact. The ECB and SEC have both flagged the [monoculture/herding risk](https://www.sidley.com/en/insights/newsupdates/2024/12/artificial-intelligence-in-financial-markets-systemic-risk-and-market-abuse-concerns).

**Implication for this desk:** assume every sleeve's half-life is shorter than its backtest implies, but *differentially*: give mechanical sleeves (momentum, short-term reversal, low-vol) steeper decay priors than judgment sleeves (value, quality). Edge migrates toward (i) data global models don't ingest — India-idiosyncratic free sources (RBI/DBIE, CCIL, AMFI, NSDL) are exactly this — and (ii) *speed of information-event alignment* rather than static factor membership. Crowding must become a measured state variable, not an assumption.

## 2. How funds actually deploy LLMs/agents — and the contamination problem is now solvable

**The production pattern that has emerged (2024–2026) is uniform across the majors: AI generates and drafts; validation pipelines and humans gate.**

- **Man Group's AlphaGPT** ([AI-Street reporting](https://www.ai-street.co/p/inside-man-group-s-alphagpt); [Man Institute, "What AI Can (and Can't Yet) Do for Alpha," Nov 2025](https://www.man.com/insights/what-ai-can-do-for-alpha)): an LLM workflow that proposes signals, writes code, and runs backtests end-to-end **before any human sees the output** — producing research concepts in minutes rather than days — but every AI-generated idea goes through the **same internal review as human research**, with explicit controls for lookahead bias and data mining. The scarce resource shifts from idea generation to validation capacity.
- **JPMorgan's "Ask David"** ([ZenML LLMOps case study](https://www.zenml.io/llmops-database/multi-agent-investment-research-assistant-with-rag-and-human-in-the-loop)): multi-agent (supervisor + specialist agents over structured data, RAG, analytics), explicitly human-in-the-loop because of acknowledged accuracy limits.
- **BlackRock's Thematic Robot** ([BlackRock](https://www.blackrock.com/us/individual/insights/ai-investing); [Addepto case study](https://addepto.com/blog/use-case-leveraging-gen-ai-and-machine-learning-in-investment-management-with-blackrocks-thematic-robot/)): LLMs map themes to second-order tradable baskets; PM input remains "crucial for correcting mistakes the LLM has made."
- **Two Sigma** ([Mike Schuster interview](https://www.twosigma.com/articles/how-to-get-the-most-from-llms/); [ICML 2025 notes](https://www.twosigma.com/articles/icml-2025-key-ideas-on-llms-human-ai-alignment-and-more/)): LLMs for productivity and feature extraction; their own research argues next-token prediction is **myopic and overly reliant on memorization** — a first-party caution against treating LLM output as alpha rather than as labor.

**The lookahead/contamination literature has matured from problem to toolkit.** [Glasserman & Lin (2023)](https://arxiv.org/abs/2309.17322) identified both **lookahead bias** (the model may know the returns that followed a headline) and the **distraction effect** (general knowledge of the company interferes with sentiment measurement — anonymized headlines actually perform *better* in-sample, especially for large caps). The 2025 answer is **chronologically consistent language models**: [He, Lv, Manela & Wu's ChronoBERT/ChronoGPT](https://arxiv.org/abs/2502.21206) — a series of checkpoints (1999–2024) each trained only on text available at that date, [open-sourced on Hugging Face](https://huggingface.co/manelalab/chrono-bert-v1-20181231) — and [Kelly et al., "Scaling Point-in-Time Language Models" (NBER w35247)](https://www.nber.org/system/files/working_papers/w35247/w35247.pdf), which industrializes the idea. Their finding: with chrono-consistent models, real-time news-based return prediction achieves Sharpe comparable to much larger contaminated models — lookahead bias is real but **modest and now measurable**, and there is finally an auditable way to backtest text signals.

**Implication for this desk:** the frozen rule "LLM-generated backtests inadmissible" was correct in 2024 and remains correct **for frontier-model-derived signals**; but vintage-stamped chrono-consistent checkpoints are a different object — auditable, point-in-time, free — and can be admitted under the existing vintage-manifest discipline. Separately, the AlphaGPT pattern maps perfectly onto a 2-person desk (Claude = hypothesis factory, principal = review gate), with one non-negotiable addition: **every AI-generated candidate must auto-increment the trial ledger**, because agentic throughput turns the multiple-testing problem from chronic to acute (see §6).

## 3. Regime instability is real; the recommended posture is ensembles + shrinkage, not free online learning

**Macro relationships have demonstrably broken.** The stock–bond correlation — the core diversification assumption of two generations of multi-asset models — flipped from a 20-year average of **−0.10 to +0.66 (36-month, Dec 2024)** ([CFA Institute](https://rpc.cfainstitute.org/blogs/enterprising-investor/2026/why-static-portfolios-fail-when-risk-regimes-change); [AQR](https://www.aqr.com/Insights/Research/Journal-Article/A-Changing-Stock-Bond-Correlation); [Morningstar](https://www.morningstar.com/portfolios/what-higher-inflation-means-stock-bond-correlations)). The driver is regime-level (inflation above target, supply shocks, policy reaction) — i.e., the *relationship between blocks* moves, not just the blocks. A portfolio optimized for the 2020 regime was decimated in 2022 and vice versa.

**What the estimation literature recommends** ([TVP-VAR lineage](https://arxiv.org/pdf/2512.20152); [self-adaptive forecasting survey 2022–2024](https://www.researchgate.net/publication/391980915_Self-Adaptive_Real-Time_Time_Series_Forecasting_A_Survey_of_Methods_and_Trends_2022-2024); [CFA Research Foundation, Ensemble Learning in Investment](https://rpc.cfainstitute.org/research/foundation/2025/chapter-4-ensemble-learning-investment); [shrinkage-combination literature](https://www.sciencedirect.com/science/article/abs/pii/S0169207021000650)):

1. **Ensembles beat single models** specifically in low signal-to-noise, regime-shifting, high-dimensional settings — via diversity, not via finding the one right model.
2. **Shrinkage toward stable baselines** improves forecasts on average, with small and configuration-dependent gains — it is cheap insurance, not alpha.
3. **Drift detection + rejection beats silent adaptation**: the well-behaved adaptive systems *detect* an unseen regime, *widen uncertainty and de-risk*, and only then re-learn — they do not chase the new regime with full leverage.
4. Fully online learning of core parameters is where the failure stories live; the March 2020 evidence ([Medallion vs RIEF](https://www.institutionalinvestor.com/article/2bswms7wco7as686o8ikg/portfolio/renaissances-medallion-fund-surged-76-in-2020-but-funds-open-to-outsiders-tanked)) is often misread — the distinction that mattered was *pre-built* regime-conditional behavior vs static parameters, not live refitting.

**Implication for this desk:** the ladder's fixed block budgets should stay fixed (governance, §6). What should change: R should become the **median of an ensemble of pre-registered grid variants** rather than a single specification; within-block weights may adapt **slowly, within pre-registered bounds, shrunk toward the frozen prior, with hysteresis** — and the system's first response to detected drift should be uncertainty-widening (de-risking via the existing bucket policy), never parameter-chasing. This is compatible with the Hamilton-filter/no-fitted-regime-switching estimation standards as-is.

## 4. India 2024–2026: regulation is re-pricing the playing field faster than competition is

**Derivatives crackdown (the dominant structural event).** SEBI's [October 2024 six-measure package](https://www.business-standard.com/amp/markets/news/sebi-announces-six-key-changes-to-curb-speculation-in-derivatives-trading-124100101316_1.html): one weekly-expiry index per exchange (NSE→Tuesday, BSE→Thursday after the [2025 expiry-day reshuffle](https://www.venturasecurities.com/blog/changes-in-expiry-nse-and-bse/)), minimum lot ₹15 lakh, upfront option-premium collection (Feb 2025), removal of expiry-day calendar-spread margin benefit, and ≥4 intraday position snapshots. The [Budget 2024 STT hike](https://www.business-standard.com/amp/budget/news/budget-2024-steep-stt-increase-to-tame-retail-frenzy-in-derivatives-market-124072301145_1.html) (effective Oct 1, 2024) raised futures STT **0.0125%→0.02%** of price (sell side) and options STT **0.0625%→0.1% of premium**. Then the [September 2025 circular](https://www.business-standard.com/markets/news/sebi-stricter-intraday-position-limits-options-market-regulation-125090200971_1.html) introduced **delta-based (futures-equivalent) intraday position limits**: net ₹5,000cr / gross ₹10,000cr FutEq per entity, effective Oct 1, 2025. Context: [retail F&O losses hit ₹1.06 lakh crore in FY25 with ~90% of participants losing](https://www.moneylife.in/article/106-lakh-crore-lost-by-individual-traders-in-fo-in-fy2425-govt-confirms-sebi-action-on-4-entities-for-market-abuse/79124.html) — the regulator's revealed intention is to keep shrinking speculative retail flow.

**Retail algo regulation.** SEBI's [Feb 2025 retail-algo framework](https://www.shareindia.com/knowledge-center/algo/latest-sebi-regulations-2025-what-algo-traders-need-to-know) (effective Aug 2025, fully mandatory April 2026): exchange-assigned **Algo-IDs on every automated order**, whitelisted static IPs, broker empanelment of algo providers, Research Analyst registration for black-box vendors.

**Passive/SIP structural bid.** Passive AUM share rose [11%→~17% of MF industry, Aug 2021→Sep 2025](https://www.businesstoday.in/mutual-funds/story/passive-funds-gain-ground-as-indian-investors-embrace-low-cost-strategies-amid-market-volatility-495918-2025-09-26); [SIP inflows crossed ₹3 trillion in calendar 2025](https://www.business-standard.com/amp/finance/news/sip-inflows-cross-rs-3-trillion-2025-offset-lumpsum-decline-125122600897_1.html); [index-fund folios up 13x in four years, with factor/momentum funds taking roughly half of factor-fund inflows](https://www.businesstoday.in/mutual-funds/story/indias-mutual-fund-market-rapid-growth-etfs-index-funds-passive-investments-502779-2025-11-19). Nifty momentum indices (200 Momentum 30, 500 Momentum 50, Midcap 150 Momentum 50) now carry real AUM. Meanwhile [FII ownership sits at a 10-year low and India's MSCI EM weight fell from ~22% (late 2024) to ~13% (early 2026)](https://www.ssga.com/us/en/institutional/insights/systematic-active-monthly-april-2025).

**What this implies — which edges strengthen vs die:**

- **Dying/compressed:** anything harvesting undifferentiated retail option flow (expiry-day effects, weekly-option premium selling on discontinued expiries) — killed by *regulation*, not competition, which means the death is a **dated structural break**, not gradual decay. Old backtests spanning these breaks are contaminated.
- **Re-priced:** the desk's hedge-cost arithmetic. The index-futures ~5.7bps round-trip figure predates the STT hike (futures sell-side STT alone is now 2bps); the 0–150% hedge grid needs cost re-estimation per instrument and — at the top of the Conservative book (₹25,000cr with a large hedge ratio) — the **FutEq position limits become a genuine hard constraint** that must live inside the hedge grid as a capacity ceiling, potentially forcing option-spread hedges or gross reduction instead of futures.
- **Strengthening:** (i) flow-anchored signals — SIP persistence, AMFI monthly flows, NSDL FPI, index-inclusion/rebalance mechanics — because passive growth makes flows larger, more rule-driven, and more forecastable; (ii) mid/small-cap cross-sectional alpha for the Aggressive book — FII exit + retail cash-market retreat leaves ranks 500–750 less arbitraged, though [liquidity/tracking evidence](https://www.axismf.com/mutual-fund-knowledge-centre/articles/passive-and-index-funds-in-india-in-2026) says capacity there is execution-constrained (the desk's days-to-build caps are the right tool); (iii) **published-momentum crowding monitoring in India specifically** — momentum is the first factor to become genuinely crowded in India via factor funds, and it is exactly the "mechanical" class that §1 says decays fastest once crowded.

## 5. What signal death looks like operationally, and retirement best practice

The operational picture from practitioners ([WorldQuant-style signal lifecycle](https://youngandcalculated.substack.com/p/how-quant-hedge-funds-actually-build); [Resonanz due-diligence framework](https://resonanzcapital.com/insights/quant-hedge-funds-in-2026-a-due-diligence-framework-by-strategy-type); [signal-decay monitoring practice](https://www.wrightresearch.in/quant-glossary/signal-decay/)):

- **Death is gradual then sudden:** declining rolling hit rate → live-vs-backtest Sharpe ratio degrading → drawdown beyond the signal's own historical envelope → correlation of the signal's P&L with crowding proxies spiking during unwinds. A widely used rule: **unexplained signals get 5–7.5% drawdown budgets** to live or die; explained signals get regime-conditional review instead.
- **The lifecycle is a recycling plant, not a museum:** new signals deploy at reduced weight → persistent underperformance triggers *automatic* down-weighting → failure to recover triggers decommissioning → the library continuously turns over. The kill decision is made by pre-set rule, not by fresh debate at the moment of pain.
- **Crowding measurement is mature enough to borrow:** [MSCI's integrated factor crowding model](https://www.msci.com/documents/10199/acf506d5-4254-b85f-e213-eaef95661970) combines valuation spreads, short-interest spreads, pairwise correlation, factor volatility, and reversal profitability; [market-derived indicators are available daily while ownership data lags weeks/months](https://insights.finominal.com/research-factor-crowding-model/). All ingredients except short interest are computable from the desk's free Indian data (valuation spreads on own sleeves, futures OI, factor-fund AUM/flows from AMFI).
- **Sequential detection works but must be self-calibrated:** CUSUM-family monitors ([backward CUSUM for real-time monitoring](https://arxiv.org/pdf/2003.02682)) are the right statistical machinery — sequential, no lookahead, cheap — but [textbook threshold calibration (Siegmund ARL) misses by ~5x on real financial data](https://www.mql5.com/en/articles/23043), so false-alarm rates must be calibrated on the desk's own bootstrapped history, and the detector should act as a **reduce-only overlay on sizing, decoupled from entry logic**.
- **Retirement is not deletion.** The quant-winter recovery (value 2021–2023) proves signals resurrect. Best practice: retired signals move to a paper-traded archive with pre-registered resurrection criteria (fresh out-of-sample evidence + crowding cleared), so re-admission is a rule, not a nostalgia trade.

## 6. The counterargument: what must stay slow — over-adaptation kills funds

**Quant winter 2018–2020 is the canonical evidence.** Only [15% of quant funds beat benchmarks in 2018–19](https://www.firstsentierinvestors.com/is/en/professional-investor/insights/lessons-from-the-quant-winter.html); the [Robeco/Blitz post-mortem](https://www.robeco.com/en-int/insights/2021/02/the-quant-equity-crisis-of-2018-2020-cornered-by-big-growth) shows the only escape was owning the largest, most expensive growth stocks — and First Sentier's **"oracle test"** shows that even *perfect foresight* of factor returns would not have justified repositioning a diversified factor model much differently. The funds that died were disproportionately those that capitulated — de-weighted value at the trough or refit models to the 2019 regime — right before the 2021–2023 value recovery. **Over-adaptation is capitulation with better branding.** Renaissance provides the mirror image: [no intervention through the 2007 quant quake (finished +85.9%) and Medallion +76% in 2020](https://medium.com/@navnoorbawa/why-renaissances-medallion-made-76-while-their-own-rief-lost-22-6-in-2020-1ed318548100) on pre-built systematic behavior.

**The multiple-testing problem gets worse, not better, in an AI age.** [Harvey & Liu](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=3073799) estimate **27–53% of published anomalies are false discoveries**; that was at *human* research throughput. An agentic hypothesis factory (§2) multiplies trials by orders of magnitude — which mechanically inflates the best backtest found. The desk's frozen standards (pre-registration, trial ledger, deflated Sharpe with trial counts, purged CV) are precisely the technology that scales to this; they must be wired *into* the AI workflow (auto-metered trials), not run alongside it on trust.

**What therefore stays frozen, with evidence-backed confidence:** Stage 1 autonomy and the switchable advisory-only overlay (Renaissance discipline evidence); the binding drawdown governor and asset-mix-as-policy (2022 stock-bond regime break shows optimizers fail exactly when needed); pre-registration and estimation standards (Harvey; AI throughput); human veto as reduce-only (every major fund's deployment pattern in §2 independently converged on this). The correct division: **fast layers** (data ingestion, monitoring, hypothesis generation, execution scheduling) and **slow layers** (block budgets, governance, kill *rules*, capital preservation). The slow layers are not a legacy cost — they are the anti-monoculture, anti-capitulation edge that homogenized AI competitors will lack.

## Design requirements for 2026–2040 (synthesis)

1. **Decay-aware sizing by signal class.** Replace the uniform published-alpha haircut with class-conditional decay priors: mechanical sleeves (momentum, reversal, low-vol) get steeper haircuts and shorter review cycles than judgment sleeves (value, quality). Half-life re-estimation feeds the haircut continuously, shrunk toward the class prior.
2. **A crowding state variable, reduce-only.** Daily market-derived crowding monitor per sleeve (own-factor valuation spread, futures OI, AMFI factor-fund flows/AUM, pairwise-correlation spikes) acting like Tier-C: it can only throttle, never add. India momentum is the first sleeve it will bite.
3. **AI as a metered hypothesis factory inside pre-registration.** Claude generates candidates, writes code, runs purged CV end-to-end; every candidate auto-registers in the trial ledger before results are viewed; the principal reviews only pre-registered survivors. Throughput scales; standards don't move.
4. **Chrono-consistent LLMs as the only admissible text-signal path.** Vintage-stamped open checkpoints (ChronoBERT/ChronoGPT lineage) + entity anonymization; frontier-model backtests stay inadmissible.
5. **Bitemporal feature store; research = production code path.** Extend vintage manifests to as-of queries over both event time and knowledge time (open-source: Iceberg/DuckDB class tooling); one feature registry both backtests and live trading call.
6. **Regulatory-break registry.** India's edge-relevant breaks are dated regulatory events (STT Oct-2024, weekly-expiry consolidation, expiry-day moves 2025, FutEq limits Oct-2025, Algo-ID Apr-2026). Backtests must split on these dates; calendar-block signals get versioned per regime.
7. **Hedge grid rebuilt as a constrained object.** Post-STT cost re-estimation per instrument; FutEq position limits (net ₹5,000cr intraday / gross ₹10,000cr per entity) modeled as a hard capacity ceiling that binds at the Conservative book's top end — the grid must know when 150% hedging is regulatorily infeasible and substitute option structures or gross reduction.
8. **Ensemble regime score with bounded, shrunk adaptation.** R = median of pre-registered grid variants; within-block weight drift allowed only within pre-registered bounds with hysteresis; first response to detected drift is uncertainty-widening/de-risking, never refitting.
9. **Sequential kill-switch machinery with death certificates at birth.** Every signal registers its retirement criteria on day one (drawdown budget, live-vs-backtest ratio floor, hit-rate floor, crowding ceiling); CUSUM monitors calibrated on own bootstrapped data; tiered response (auto down-weight → quarantine → retire → paper-traded archive with resurrection criteria).
10. **Anti-capitulation rule (governance).** No parameter, budget, or model-structure change may be initiated while the affected sleeve is inside a drawdown beyond a pre-set depth; changes only on scheduled review dates or from strength. This is the single cheapest lesson of 2018–2020.
11. **Deliberate anti-monoculture data policy.** Weight India-idiosyncratic sources no foundation model ingests (RBI/DBIE, CCIL, NSDL granularity, AMFI) over globally consensus feeds; the homogenization literature implies this is where residual edge concentrates as AI saturates consensus data.
12. **Flow-signal block as a growth area.** Passive/SIP structural bid makes flows larger and more rule-driven through 2040: index-inclusion/rebalance mechanics, SIP persistence, FPI positioning — natural candidates for the next pre-registered research cycle.

The architecture verdict: pipeline v1's skeleton (autonomous Stage 1, policy-not-optimized asset mix, binding drawdown governor, pre-registration) is the *right* skeleton for an AI-saturated 2026–2040 — the required changes are additive (crowding block, decay classes, bitemporal store, metered AI research loop, regulatory-break registry, constrained hedge grid) rather than structural. Nothing found in this research argues for re-architecting the frozen core; nearly everything argues for hardening it.

Caution: Segmenting shrinks samples, colliding with the frozen no-fitted-regime-switching-under-10-transitions rule; some post-break signals will simply be unestimable for years — the registry must be allowed to say 'insufficient data' rather than force a fit

Why 2026-2040: As AI saturates consensus data, residual edge concentrates in non-consensus local data and in structurally growing rule-driven flows; this is the desk's durable comparative advantage over homogenized competitors. Caution: Flow signals are capacity-limited and partly seasonal, and India's passive share is still small relative to the US — size expectations as a complement to the factor sleeves, not a replacement

### Survey for the cycle-stack desk (principal + Claude) — free data only, vintage-stamped, no lookahead

## 0. Executive summary

The desk's current data list (RBI DBIE, NSE/BSE bhavcopy, AMFI, NSDL FPI, MOSPI, CCIL, BIS, IMF, FRED, World Bank, WGC, exchange filings, Kaggle/HF) covers **prices, macro aggregates, and headline flows** but misses the three richest free layers India offers:

1. **Ownership & positioning micro-data** — monthly MF scheme portfolios, quarterly shareholding patterns, insider (PIT) and SAST/pledge disclosures, bulk/block deals, participant-wise derivatives OI, SLB, margin-funding books. These are *disclosure-mandated, timestamped at dissemination, and mostly PIT-clean* — the closest thing a free-data desk gets to 13F-style edge, at monthly rather than quarterly cadence.
2. **Digital-public-infrastructure (DPI) exhaust** — GST collections, e-way bills, UPI, VAHAN vehicle registrations, FASTag tolls, Grid-India power demand, PPAC fuel sales, rail freight, DCA daily food prices. India is the only major market whose *official statistical system emits daily/monthly administrative exhaust for free*; RBI itself nowcasts GDP from these (RBI WPS 03/2020, dynamic factor model). This is the natural upgrade to the macro-credit block.
3. **Event/text feeds** — BSE/NSE corporate announcements (exact dissemination timestamps), rating-agency press releases, SEBI processing pipelines (DRHP status), IBBI insolvency data. For a 2-person desk with Claude, the binding constraint is no longer access but *processing discipline* — which is exactly where the desk's Tier-C reduce-only clamp already fits.

The dominant architectural implication: most of the highest-value additions are **perishable or backfilled web publications**, so the single biggest data-layer upgrade is a **capture-on-publication WORM archiver + bitemporal (event-time / knowledge-time) feature store**. Signal ideas decay (McLean–Pontiff); a clean point-in-time archive of Indian disclosures *appreciates* — it is the desk's only durable data asset.

| **PMI** | Access, not revision | Headline via press release only; archive releases (no flash/final issue in India) |
| **MF stress tests** | Short history (Feb-2024→) | Insufficient for regime fitting per desk standards; usable as a level/state input only |
| **Kaggle/HF Indian datasets** | **Provenance & backfill unknown** | Treat as exploration only; never admissible for pre-registered validation — rebuild from primary sources |

**Cross-cutting rule the table implies:** every one of the high-value additions is either (a) restated silently, (b) perishable, or (c) timestamp-ambiguous. The remedy is one architectural feature, not per-source hacks: **bitemporal storage (event_time, knowledge_time) over a WORM raw-capture layer.**

## 4. What appreciates 2026–2040

1. **Ownership/positioning disclosures** — as Indian ownership domesticates (DII + SIP flows structurally exceed FPI), the MF monthly portfolios + SIP data become the map of the *marginal buyer*; crowding measurement moves from nice-to-have to survival (the drawdown governor's worst episodes will be crowded-unwind episodes).
2. **DPI exhaust** — uniquely Indian and *broadening*: UPI, GSTN, VAHAN, FASTag, ONDC, Account Aggregator statistics. Coverage and granularity rise every year while their marginal cost stays zero. By the 2030s this stack plausibly rivals paid alternatives (CMIE) for macro nowcasting.
3. **Derivatives microstructure data** — India is the world's largest options market by contracts; SEBI keeps re-regulating it (lot sizes, expiries, position limits). Each regulatory reset is a regime break that *only positioning data can see quickly*. Value rises precisely because history keeps breaking — favouring state-variable use over fitted models (consistent with the desk's <10-transitions rule).
4. **Text/filings at dissemination timestamps** — in AI-saturated markets the alpha half-life of *reading* announcements collapses toward zero for large caps, but ranks 250–750 stay under-read; a 2-person desk with Claude has comparative advantage exactly there — under the Tier-C clamp.
5. **Corporate bond & credit data** — CCIL/exchange bond trades, EBP issuance, rating actions: the corporate bond market's deepening (and the desk's ≤70% debt sleeve) makes a free credit-spread curve progressively more informative for the credit-cycle state.
6. **What depreciates:** headline FPI flow signals (fully arbitraged, small autocorrelation), Google-Trends-style attention (published, weak, non-PIT), and any Kaggle-hosted derivative datasets.

## 5. The data-books angle — canon and prescriptions for a 2-person desk

| Book | Key prescriptions relevant here |

## 6. Integration blueprint into pipeline v1 (respecting all frozen constraints)

**Data layer (upgraded):**
- Layer 0 — *Capture daemon*: scheduled fetch of every perishable/restated source (NSE EOD files, AMFI/AMC portfolios, Grid-India PDFs, PIB releases, VAHAN snapshots, rating press releases, Google Trends, exchange announcements) into immutable raw blobs with fetch timestamps. Cheap, automatable by Claude-written cron jobs; the desk's only appreciating asset.
- Layer 1 — *Bitemporal feature store*: every row carries (event_time, knowledge_time, source_version); manifests become queries ("as known on date D"), eliminating per-study lookahead audits.
- Layer 2 — *Entity master*: ISIN-keyed mapping across exchanges, AMCs, rating agencies, filings; survivorship-free NIFTY 750 membership reconstructed from index press releases.

**Risk engine:** DPI nowcast factor → macro-credit block; rating-action diffusion → credit-cycle state; participant-wise OI z-scores + MWPL ban breadth + India VIX/IV surface → fast-stress and sentiment blocks (Tier-C, reduce-only, within the frozen fixed block budgets); SIP stoppage + demat additions + IPO pipeline → valuation/sentiment block.

**Return engine:** pledge-change and insider-net-buy as cross-sectional conditioning variables (published → haircut); MF-portfolio crowding score as a *penalty* on momentum sleeve sizing and as input to the buildable-within-half-life cap (stress-test days-to-liquidate directly parameterises it for ranks 250–750).

**Research process:** dataset due-diligence scorecard (Denev–Amen) gated through pre-registration; every new source serves a **6–12 month live-capture probation** before its history is admissible; Kaggle/HF demoted to exploration-only.

**Execution:** index-rebalance flow calendar and MWPL ban-list awareness added to the execution scheduler (avoid supplying liquidity into reconstitution days for the Conservative book; never initiate into ban-period names).

All of this fits the frozen constraints: no new AI discretion in Stage 1, asset mix untouched, free data only, estimation standards preserved (state variables and ranks, not fitted regime models, for the short-history sources).
